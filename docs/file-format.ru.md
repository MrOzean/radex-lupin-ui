# Формат записи `.lupinlab`

Собственный локальный формат Lupin Light Lab для полного потока измерений. Файл не требует сервера и открывается без подключённого прибора.

## Структура

| Поле | Размер | Описание |
|---|---:|---|
| Magic | 8 байт | ASCII `LUPINLAB` |
| Header length | 4 байта | `uint32 LE`, размер JSON-заголовка |
| Header | переменный | UTF-8 JSON |
| Samples | `sampleCount × 4` | `float32 LE`, необработанные отсчёты |

В заголовке версии 1 сохраняются:

- даты создания, начала и окончания записи;
- частота дискретизации и число отсчётов;
- тип измерения, профиль помещения/работы, диапазон спектра, корректирующий множитель и состояние НЧ-фильтра;
- комментарий, источник и доступные метаданные прибора;
- версия формата и кодировка данных.

При открытии фильтр и коррекция применяются к исходным отсчётам заново. Поэтому в архиве можно менять параметры анализа без двойной обработки сигнала.

При 6000 Гц поток float32 занимает 24 000 байт/с: около 1,44 МБ/мин, 86,4 МБ/час или 2,07 ГБ/сутки без учёта заголовка.

## Почему так

Формат разделяет данные по их природе: JSON удобен для эволюции метаданных, а float32 — для компактного и точного хранения измерений. Такой подход сохраняет биты исходного `Float32Array`, не требует текстового разбора миллионов чисел, использует меньше памяти и позволяет читать/писать отсчёты блоками. Заголовок и payload независимо проверяются, поэтому внешним инструментам не нужен специальный JSON-парсер потока измерений.

Сравнение одного реального пакета LUPIN (6000 отсчётов):

| Представление | Без сжатия | gzip-9 |
|---|---:|---:|
| float32 LE | 24 000 Б | 16 729 Б |
| JSON с полной точностью | 111 146 Б | 43 895 Б |
| JSON с округлением до 3 знаков | 35 303 Б | 3 607 Б |

JSON с полной точностью даже после gzip оказался больше исходного float32. Округлённый JSON сжимается лучше, но уже не сохраняет исходный сигнал и поэтому не подходит для метрологии и reverse engineering. Если размер файлов станет проблемой, можно добавить `.lupinlab.gz` с теми же JSON-заголовком и float32, не меняя внутренний формат и не теряя точность.

Декодер проверяет сигнатуру, размер заголовка, обязательные поля, точный размер блока отсчётов и конечность значений. Официальные `.pulse`/`.bpulse` пока не поддерживаются; их совместимость требует отдельного исследования.
